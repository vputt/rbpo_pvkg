## Запуск

Нужен Go 1.26 или новее; проверенное окружение - Go 1.26.4, Windows amd64.

Используется стандартный пакет net/http; внешних зависимостей нет.

```powershell
go run ./cmd/server
```

Сервер запускается локально по адресу `http://localhost:8080`. Остановка - Ctrl+C.

В другом терминале:

```powershell
Invoke-RestMethod http://localhost:8080/health
```

Ожидаемый ответ - HTTP 200 и `{"status":"ok"}`.

## Текущий объём

Это ранний минимальный прототип, подготовленный для первого запуска проекта. В дальнейшем он будет дополняться основными сценариями и защитными механизмами.

Сейчас реализованы сервер, /health, модель находки и хранилище в памяти. Хранилище назначает ID и статус available, сохраняет записи и возвращает каталог. Модель: [Item](internal/domain/item.go), контракт: [ItemRepository](internal/domain/item_repository.go), реализация: [memory.Store](internal/storage/memory/items.go).

Через HTTP пока доступен только GET /health. Обработчики POST /api/items и GET /api/items, авторизация, обращения и выдача ещё не реализованы. Данные в памяти не сохраняются после перезапуска. Требования безопасности и проектные решения описывают целевое развитие продукта.

## Проверка

```powershell
go test ./...
go build ./...
go vet ./...
```

Два теста хранилища проверяют сохранение, независимость возвращённого каталога и создание уникальных ID при одновременной записи. Для проверки гонок: go test -race ./... (требуются CGO и C-компилятор).

Работоспособность сервера проверяется запросом /health. Создание и чтение находок пока проверяются только на уровне хранилища.
