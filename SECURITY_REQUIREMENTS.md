# Требования безопасности

| ID | Требование | Критерий приёмки | Связанные T / D (позднее) |
| --- | --- | --- | --- |
| SR-01 | Система разрешает регистрацию находок и изменение их состояния только пользователям с ролью «Сотрудник» (v5.0.0-8.2.1). | При попытке обычного пользователя выполнить запрос на создание карточки вещи или изменение её состояния, сервер отклоняет действие (возвращает 403 Forbidden), а состояние базы данных остаётся неизменным. | — |
| SR-02 | Система запрещает пользователю доступ к данным чужих обращений, защищая от подмены идентификатора (IDOR) (v5.0.0-8.2.2). | При попытке пользователя A запросить данные обращения пользователя B по прямому идентификатору, сервер возвращает ошибку (например, 403 или 404), чужие данные в ответе отсутствуют. | — |
| SR-03 | Система соблюдает строгую последовательность логики: выдача вещи невозможна без предварительного наличия одобренного обращения (v5.0.0-2.3.1). | При попытке сотрудника зафиксировать выдачу находки, для которой нет связанного обращения в статусе `одобрено`, действие отклоняется, статус вещи не меняется. | — |
| SR-04 | Система защищает от состояния гонки и двойного использования ресурса, не позволяя одобрить выдачу одной вещи нескольким претендентам (v5.0.0-2.3.4). | При одновременной попытке одобрить два разных обращения на одну и ту же находку, успешно завершается только одно действие. Второе обращение отклоняется сервером, повторная выдача не происходит. | — |
| SR-05 | Система возвращает в публичный каталог только разрешённое подмножество данных, скрывая закрытые признаки вещи (v5.0.0-15.3.1). | При запросе пользователем каталога находок в статусе `доступна`, в теле ответа сервера строго отсутствуют поля с закрытыми отличительными признаками, даже если они есть в базе данных. | — |
| SR-06 | Система защищена от манипуляции параметрами (Mass Assignment) при подаче обращения (v5.0.0-15.3.3). | При попытке пользователя передать в запросе на создание обращения поле состояния (например, `"status": "одобрено"`), сервер игнорирует неразрешённое поле и создаёт обращение со строго заданным начальным состоянием `на рассмотрении`. | — |
