## Запросы к запущенному серверу

| Запрос | Код | Тело ответа |
| --- | --- | --- |
| верный логин и пароль | `200` | поля `token` (43 символа) и `expires_at` на 8 часов вперёд |
| верный логин, неверный пароль | `401` | `{"error":{"code":"invalid_credentials","message":"неверный логин или пароль"}}` |
| неизвестный логин | `401` | то же тело посимвольно |
| лишнее поле `role` в теле | `400` | `{"error":{"code":"invalid_request","message":"тело запроса не разобрано: ожидаются только поля login и password"}}` |
| неразобранный JSON `{"login":` | `400` | то же тело |
| пустой объект `{}` | `401` | тело как при неверных данных |
| `GET` вместо `POST` | `405` | стандартный текст `net/http`, не конверт ошибки API |

Ответ верного входа:

```text
поля ответа: ['expires_at', 'token']
длина токена: 43
expires_at: 2026-11-25T19:26:03.992927+03:00
```

## Что лежит в таблице sessions

```text
 hash_bytes | user_id | ttl_ok | token_in_row
------------+---------+--------+--------------
         32 |       1 | t      |            0
```

`token_in_row` - результат `strpos(sessions::text, '<выданный токен>')` по всей строке таблицы: ноль означает, что токена нет ни в одном поле. `ttl_ok` - срок действия в интервале от 7 часов 59 минут до 8 часов от времени сервера БД.

## Журнал сервера

За всё время работы, включая семь запросов входа, сервер написал одну строку:

```text
2026/11/25 11:25:56 HTTP API: 127.0.0.1:8099
```

Поиск выданного токена в журнале даёт 0 вхождений, поиск слова `authorization` - тоже 0. Журналирования запросов в продукте пока нет вовсе, поэтому ни заголовки, ни тела в журнал не попадают; при появлении такого журналирования проверку нужно повторить.

## Ограничения проверки

- Проверена только выдача сессии. Проверка переданного токена, загрузка актуальной роли в серверный контекст и отказы на защищённых маршрутах не реализованы, поэтому ни один шаг будущей проверки D-01 про `401`, `403` и `404` здесь не закрыт.
- Ограничение подбора пароля не проверялось: `429`, счётчик неудачных попыток и блокировка относятся к следующему куску. Вход счётчик и блокировку не трогает - операции `IncrementLoginFailures`, `LockLogin` и `ResetLoginFailures` вне тестов нигде не вызываются, что видно поиском по коду.
- Равное время ответа на неизвестный логин и на неверный пароль измерено однократно на одной машине (181 и 182 мс). Это проверка наличия сравнения с хешем-заглушкой, а не статистическое доказательство отсутствия утечки по времени.
- Срок действия сессии проверен на значении по умолчанию 8 часов; поведение при истечении срока проверяется вместе с проверкой сессии.
- Токен выдаётся по HTTP без шифрования канала: учебный стенд, перехват трафика в границу проверки не входит.
